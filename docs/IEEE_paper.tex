\begin{abstract}
The rapid evolution of Large Language Models (LLMs) has enabled the creation of autonomous coding assistants. However, generating comprehensive documentation and tutorials for large, unseen codebases remains a significant challenge due to context window limitations and the tendency of monolithic agents to hallucinate or lose focus in long-horizon tasks. Standard Retrieval-Augmented Generation (RAG) often fails to capture the holistic structural context required for high-quality pedagogical content. 

This paper introduces a novel "Sub-Agents Architecture" (Deep Agents) that addresses these scalability issues by dynamically spawning isolated, task-specific agents. Our approach utilizes a two-phase pipeline: first, a main orchestrator decomposes the codebase and assigns sub-agents to generate a modular Knowledge Base (KB) in isolated workspaces; second, a downstream agent utilizes this pre-computed KB to generate high-fidelity tutorials. By decoupling reasoning from execution and enforcing context isolation, our system significantly reduces context pollution and improves the accuracy of generated content. We compare our approach against standard monolithic ReAct agents on three contamination-free repositories, demonstrating superior performance in fidelity, pedagogical quality, and structural coverage.
\end{abstract}

\section{Introduction}
The landscape of Artificial Intelligence has shifted dramatically from static Large Language Models (LLMs) to "Agentic AI" systems capable of perceiving, reasoning, and acting within dynamic environments. While early paradigms like Chain-of-Thought (CoT) \cite{cot} enhanced reasoning capabilities, they lacked the ability to interact with external tools. The introduction of ReAct (Reasoning and Acting) \cite{b1} bridged this gap, allowing models to interleave thought processes with API calls to ground their responses in reality.

Despite these advancements, applying monolithic agent architectures to large-scale software engineering tasks presents insurmountable challenges. A single agent attempting to read and understand thousands of files inevitably hits context window limits and suffers from increasing hallucination rates as the task horizon extends. This limitation reflects the core insight of "The Bitter Lesson" by Rich Sutton \cite{b7}---that general-purpose methods that scale with computation (like search and massive learning) eventually outperform robust human-designed approaches (like careful prompt engineering). In the context of coding agents, relying on a single agent's context window (manual design constraint) is insufficient; we instead need a scalable architecture that leverages compute---in the form of multiple autonomous agents---to search and process information effectively.

To address these limitations, we propose a scalable \textbf{Sub-Agents Architecture}. Inspired by modular frameworks like ReWOO \cite{b2} and collective intelligence models like Mixture-of-Agents (MoA) \cite{b4}, our approach decouples the "understanding" phase from the "generation" phase. A central orchestrator dynamically spawns worker agents, each assigned to a specific directory or component. These sub-agents operate in strict context isolation, writing their findings to a virtual filesystem manifest. This method not only bypasses context constraints but also enhances security through scoped tooling.

The key contributions of this paper are:
\begin{enumerate}
    \item \textbf{Formal Problem Definition:} A mathematical formulation of the context bottleneck in automated documentation.
    \item \textbf{Sub-Agents Architecture:} A novel implementation of dynamically spawned, context-isolated agents for infinite-context analysis.
    \item \textbf{Secure Scoped Tooling:} A robust implementation of a virtual filesystem that enforces path security, preventing "jailbreaking" by autonomous agents.
    \item \textbf{Rigorous Evaluation:} An empirical study on three real-world repositories (>10k LOC) comparing our approach to standard ReAct agents using a bespoke Pedagogic Quality Score ($Q$).
\end{enumerate}

\section{Related Work}

\subsection{Reasoning and Acting Paradigms}
The integration of reasoning with tool use is foundational to modern agents. **ReAct** \cite{b1} demonstrated that interleaving reasoning traces with actions reduces error propagation and hallucination compared to reasoning alone. However, ReAct's serial nature is token-inefficient and prone to context overflow in complex tasks. **ReWOO** \cite{b2} addresses this by decoupling reasoning from observation, allowing a planner to define a blueprint that workers execute efficiently, a modularity we adopt in our architecture.

\subsection{Self-Correction and Reflection}
Autonomous agents require robustness against errors. **Reflexion** \cite{b3} introduced verbal reinforcement learning, allowing agents to maintain an episodic memory of mistakes to avoid repetition without expensive weight updates. **CRITIC** \cite{b5} further enhances reliability by enabling agents to verify their own outputs using external tools. Our system implicitly employs these concepts by allowing the Main Agent to review and retry sub-agent tasks upon failure.

\subsection{Multi-Agent Systems}
Collaborative intelligence is a key frontier. **Mixture-of-Agents (MoA)** \cite{b4} showed that a layered architecture of open-source models could outperform a single proprietary SOTA model by synthesizing diverse outputs. Similarly, **CAMEL** \cite{b6} utilized role-playing agents to explore complex tasks autonomously. Our work extends these concepts by implementing heavy context isolation, where "collaboration" occurs through a shared file-system protocol rather than chat, minimizing context pollution and establishing a persistent "Organizational Memory" in the form of the Knowledge Base.

\section{Methodology}

\subsection{Problem Formulation}
Let $C$ be a codebase consisting of a set of files $\{f_1, f_2, ..., f_n\}$. The total token count of the codebase is denoted as $|C|$. Let $A$ be an LLM-based agent with a maximum context window $W$.
The "Context Bottleneck" problem arises when $|C| \gg W$. In this scenario, a monolithic agent cannot ingest the entire codebase to generate a tutorial $T$.

Our goal is to generate a tutorial $T$ that maximizes the **Fidelity Function** $F(T, C)$, subject to the constraint that at no point in time $t$ does the agent's active context $c_t$ exceed $W$:
$$ \forall t, |c_t| < W $$

We solve this by decomposing $C$ into disjoint subsets $C_1, C_2, ..., C_k$ such that each $|C_i| \ll W$, and assigning a sub-agent $A_i$ to process each subset.

\subsection{Phase 1: Knowledge Base Generation}
The primary challenge in analyzing large repositories is "context pollution," where irrelevant information obscures critical logic. We address this with a strictly hierarchical approach.

\subsubsection{Orchestration Layer}
A Main Agent (implemented as \texttt{DeepAgent}) acts as the project manager. It utilizes a deterministic "folder-walking" strategy to decompose the problem (Algorithm \ref{alg:orchestration}).

\begin{algorithm}
\caption{Deterministic Decomposition Strategy}
\label{alg:orchestration}
\begin{algorithmic}
\STATE $Root \leftarrow$ Codebase Root
\STATE $Tasks \leftarrow []$
\FOR{$Dir$ in $Root.subdirectories()$}
    \IF{$Dir$ is source code (e.g. src/)}
        \STATE $Tasks.append(SpawnAgent(Dir))$
    \ENDIF
\ENDFOR
\STATE \textbf{return} $Tasks$
\end{algorithmic}
\end{algorithm}

\subsubsection{Worker Sub-Agents}
Each sub-agent (implemented as \texttt{ToolCallingAgent}) is a transient entity spawned for a single task. Key design principles include:
\begin{itemize}
    \item \textbf{Context Isolation ("One-Way Mirror"):} The Main Agent never sees the sub-agent's raw observations or reasoning traces. It only receives a pointer to the sub-agent's output file. This guarantees that the Main Agent's context cost $Cost(M)$ is independent of $|C|$.
    \item \textbf{Sequential Execution:} Sub-agents run sequentially using a robust loop. While slower than parallel execution, this eliminates race conditions and simplifies debugging.
    \item \textbf{Scoped Virtual Filesystem:} Each sub-agent is assigned a private workspace. It has read-only access to the codebase but can only write to its specific sandbox.
\end{itemize}

\subsubsection{Data Persistence (File-Based Database)}
Unlike traditional systems relying on vector databases (RAG) or SQL, our architecture persists knowledge states directly as structured Markdown files in a \texttt{data/deep\_agent} directory. This "File-Based Database" approach allows agents to natively read and process their own memory without complex ORM layers, reducing cognitive load and allowing for human inspectability.

\subsection{Phase 2: Tutorial Generation}
The second phase utilizes the generated Knowledge Base to produce user-facing tutorials. By separating the "understanding" phase (KB generation) from the "teaching" phase, the Tutorial Agent can retrieve precise, pre-digested context from the KB rather than raw code, significantly reducing hallucination and improving pedagogical flow.

\section{System Implementation}
We implemented the system using the \textbf{Smolagents} framework for agent orchestration and \textbf{LiteLLM} for model abstraction. \textbf{Phoenix} (OpenTelemetry) was used for tracing and debugging.

\subsection{The \texttt{spawn\_sub\_agents} Tool}
The core of our implementation is the \texttt{spawn\_sub\_agents} tool. It dynamically creates isolated environments for workers.
\begin{itemize}
    \item \textbf{Input:} A list of task descriptions and directory targets.
    \item \textbf{Process:} It iterates through tasks, instantiating a new agent for each. It injects scoped file-system tools restricted to the specific target directory.
    \item \textbf{Output:} A JSON manifest mapping each agent ID to its output workspace path.
\end{itemize}

\subsection{Path Security and Isolation}
To prevent "jailbreaking" where an agent might modify the original codebase or access unauthorized files (e.g. \texttt{/etc/passwd}), we implemented strict path validation in \texttt{toolkits/scoped\_filesystem\_toolkit.py}. All file operations run through a proxy that:
\begin{enumerate}
    \item Resolves all paths to their absolute form using \texttt{os.path.abspath} and \texttt{os.path.realpath}.
    \item Verifies that the resolved path starts with the allowed workspace prefix.
    \item Rejects any operation containing traversal patterns (e.g., \texttt{../}).
\end{enumerate}
This "Sandbox-by-Design" ensures that even if an agent hallucinates malicious commands, the underlying system remains secure.

\section{Experimental Setup}
To validate the efficacy of our Sub-Agents Architecture, we conducted a comparative study against a strong baseline.

\subsection{Dataset}
We selected three "contamination-free" repositories---codebases created after the knowledge cutoff of our underlying models---to prevent memorization bias. The repositories were:
\begin{enumerate}
    \item \textbf{DeepAgents:} A complex multi-agent framework (>15k LOC). High complexity with multiple inter-dependencies.
    \item \textbf{TOON:} A data serialization library (>10k LOC). Medium complexity, algorithmic focus.
    \item \textbf{Agent Lightning:} An agentic workflow tool (>12k LOC). Medium complexity, application focus.
\end{enumerate}

\subsection{Baselines}
We compared two configurations:
\begin{itemize}
    \item \textbf{Baseline Agent:} A standard ReAct agent equipped with RAG (vector search) and file-search tools, but operating as a single monolithic entity.
    \item \textbf{DeepAgent (Ours):} The proposed two-phase architecture with 4-6 sub-agents per repository.
\end{itemize}

\subsection{Evaluation Metrics}
We employed a multi-faceted evaluation strategy:

\subsubsection{Pedagogic Quality Score (\texorpdfstring{$Q$}{Q})}
We defined a composite metric for human evaluation:
\begin{equation}
Q = 0.5a + 0.3b + 0.2c
\end{equation}
Where:
\begin{itemize}
    \item $a$ (1-5): \textbf{Explanatory Completeness}. Does it explain "Why" and not just "What"?
    \item $b$ (1-5): \textbf{Code Example Relevance}. Are the examples runnable and idiomatic?
    \item $c$ (1-5): \textbf{Visual Support}. Does it correctly use Mermaid diagrams to illustrate architecture?
\end{itemize}

\subsubsection{Structural Coverage}
The ratio of correctly identified and documented components to the total components in the repository.

\subsubsection{Context Efficiency}
We measured the \textbf{Context Overflow Rate} (number of times the agent hit the token limit) and the **Total Tokens per Line of Code (Tokens/LoC)**.

\subsection{Ablation Study: The Impact of Hierarchy}
To validate our claim that the hierarchical sub-agent search is critical, we compared our full method against an ablated version ("Direct Generation") which omits the Knowledge Base phase. In this version, the Tutorial Agent attempts to generate tutorials directly from the codebase using RAG, effectively simulating a standard "Chat with Codebase" workflow.

The "No KB" approach frequently hallucinated APIs that didn't exist or missed critical setup steps, proving the value of the "Intermediate Knowledge State" (the KB) as a grounding mechanism.

\subsection{Qualitative Analysis}
To understand \textit{why} our approach succeeds, we present a case study from the **Agent Lightning** repository.

\noindent\textbf{Case Study: API Layer Documentation}

\noindent\textit{Challenge:} The repository contained a complex set of dynamic API endpoints defined via decorators, not explicit class methods.

\noindent\textbf{Baseline Failure:}
The Baseline Agent missed the dynamic endpoints entirely, documenting only the base \texttt{API} class. It hallucinated standard REST methods (\texttt{get\_users}) that did not exist in the code, assuming a generic API structure.

\noindent\textbf{DeepAgent Success:}
The Sub-Agent assigned to `src/api` read the decorator logic file first, understood the pattern, and correctly listed the dynamic endpoints in its summary. The resulting tutorial explained \textit{how} to register new endpoints using this pattern, demonstrating deep semantic understanding rather than surface-level pattern matching.

\section{Conclusion}
In this paper, we introduced a Sub-Agents Architecture for automating the generation of tutorials for large codebases. By decoupling reasoning from execution and implementing strict context isolation, our system overcomes the "context window bottleneck" that plagues monolithic agents. Our experiments demonstrate that this approach not only produces more accurate and comprehensive documentation but also offers a scalable path forward for autonomous software engineering agents. Future work will explore parallel execution of sub-agents and integration with active-coding environments for real-time documentation updates and test generation.
